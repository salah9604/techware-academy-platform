# Techware — ابدأ هنا

نسخة أولية متصلة بـFirebase، للتجربة بحسابات حقيقية بعد نشر القواعد. الواجهة React + TypeScript والتنسيق CSS؛ البناء النهائي HTML/JavaScript ثابت لا يحتاج سيرفر مدفوع. مشروع Firebase هو `techware-instructor`.

**لم يتم نشر هذه النسخة أو تعديل مشروعك الفعلي من هنا.** الاختبارات تمت على Emulator ببيانات وهمية. لا توجد مفاتيح Service Account في الملفات.

## 1. تشغيل Windows

فك الملف في مجلد جديد للحفاظ على نسختك السابقة، وافتح Git Bash داخل المجلد الذي يحتوي package.json:

```bash
node -v
npm install -g pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

Node يجب أن يكون 22.13 أو أحدث؛ Node 24 الذي ثبّتّه مناسب. افتح الرابط الظاهر في الطرفية، عادة `http://localhost:5173`، واترك الطرفية مفتوحة. `/demo` معاينة محلية منفصلة لا تمنح حساباتها صلاحيات Firebase.

## 2. نشر القواعد وتجهيز الدخول

من Firebase Console للمشروع الحالي:

1. Authentication → Sign-in method: فعّل Google و/أو Email/Password. لا تحتاج Phone Auth.
2. Authentication → Settings → Authorized domains: أضف `localhost` إن لم يكن موجودًا، بدون بروتوكول أو منفذ.
3. احتفظ بنسخة من قواعدك الحالية. الملف `firebase/firestore.rules` يدمج القواعد التي أرسلتها مع قواعد المنصة الجديدة.

التغييران المقصودان في النظام القديم: إنشاء مستخدم جديد يسمح بدور **pending بدل instructor**، والحساب المرتبط بالإيميل يحتاج بريدًا موثّقًا. المدربون الموجودون بالفعل يظلون معتمدين؛ راجع الحسابات التي دخلت عبر التسجيل الذاتي قبل الإطلاق.

**لو شاشة التسجيل القديمة تنشئ role: instructor، عدّل إنشاء الملف إلى role: pending.** الإدارة تعتمد الحساب لاحقًا بتعديل users/{uid}.role إلى instructor. وإلا ستُرفض محاولة التسجيل القديمة بالقواعد الجديدة.

من مجلد النسخة الجديدة بعد المراجعة:

```bash
npx -y firebase-tools@latest login
npx -y firebase-tools@latest deploy --only firestore:rules --config firebase.portal.json --project techware-instructor
```

الأمر ينشر قواعد الوصول فقط، ولا ينقل أو يحذف بيانات الطلاب ولا يفعّل Billing.

## 3. تفعيل الإدارة وإضافة الحسابات

ادخل بنفس حساب الإدارة القديم، ثم «أنا مسؤول النظام القديم» → «تفعيل حساب الإدارة الحالي». القواعد تتحقق من وجود role: admin في users القديمة؛ الاسم أو الإيميل وحده لا يكفي. الحساب القديم المرتبط بالإيميل يحتاج email_verified. إذا لم يوجد Admin قديم، مسؤول مشروع Firebase يضيف ملف UID الصحيح من Console؛ لا تفتح إنشاء Admin للعامة.

من «الحسابات والكورسات»:

1. أضف الكورسات ومساراتها والكورس التالي.
2. المستخدم يدخل بـGoogle ويعطيك UID، أو تنشئ حساب Email/Password له من Authentication → Users. انسخ UID واربطه بالاسم والدور. إنشاء سجل في المنصة لا ينشئ كلمة مرور أو حساب Authentication.
3. اربط المدربين والطلاب، ثم ولي الأمر بأبنائه. يمكن تسجيل كورسات الطالب المكتملة ومستويات Robotics المكتملة لشروط المسابقات.
4. أنشئ المجموعة وحدد الكورس والمدرب والطلاب والموعد والمستوى والمحاضرة.
5. جرّب الدخول بحساب طالب ومدرب وولي أمر قبل مشاركة الرابط على نطاق واسع.

الربط بالـUID وليس تشابه الأسماء. بيانات المنصة في `academyPortal/techware` منفصلة عن مجموعات البيانات القديمة. **لم يتم استيراد بيانات النظام القديم تلقائيًا.** بيانات المعاينة لا تُنسخ إلى Firebase.

## ما يعمل في النسخة

- صلاحيات الأدوار الأربعة، المجموعات والكورسات والمحاضرات والتاسكات والصور والمراجعة والحضور.
- نسبة إرسال مستقلة عن عدد التاسكات المعتمدة، ورحلة التعلم والكورس التالي.
- محادثات الطالب والمدرب مع وصول الإدارة؛ ولي الأمر لا يرى المحادثة الخاصة.
- الأبناء والملاحظات المسموح بها والاستحقاقات وحالة الدفع. الدفع تسجيل إداري وليس بوابة تحصيل.
- الأحداث والمسابقات وطلبات الاشتراك وموافقة ولي الأمر والإدارة. اعتماد المشاركة يحدّث عداد السعة في نفس عملية الحفظ لمنع تجاوزها بالتزامن.
- تحديثات وتنبيهات داخل المنصة أثناء فتحها؛ **Push وإشعارات الهاتف في الخلفية غير مفعّلة**.
- إحصائيات وتقرير CSV. سجل النشاط مساعد للمتابعة وليس سجل تدقيق خادميًا يضمن تسجيل كل عملية من عميل معدّل.

## الصور وعدم الدفع

لا تستخدم النسخة Cloud Storage أو Functions أو TTL. الصور الصغيرة تحفظ كمستندات منفصلة في Firestore، كحل محدود للتجربة الأولى وليس مخزن صور واسعًا.

- 5 صور للمحاولة، و220 ألف بايت للصورة بعد الضغط؛ القواعد تسمح بـ300 ألف حرف للصورة بعد ترميز data URL.
- إذا بقيت اللقطة كبيرة يُطلب قص الكود للحفاظ على الوضوح. تنزيل الصور عند الطلب.
- يحفظ أحدث نص وتسليم؛ صور المحاولات السابقة تبقى مرتبطة بالتاسك للتنظيف، لكن عرض سجل المحاولات الكامل غير منفذ في وضع Firebase.
- الحذف بعد اعتماد التاسك ومرور 90 يومًا على وقت مراجعة الخادم، إلا لو اختير «الاحتفاظ بالصور».
- تنظيف تلقائي عند فتح حساب الإدارة مرة يوميًا لكل متصفح، وزر يدوي. **لو المنصة مقفولة لا يجري حذف في الخلفية.** نتائج التاسكات ونصوصها تبقى محفوظة.
- أقصى عدد 20 محاولة لكل تاسك، وفاصل 30 ثانية بين تحديثات التسليم.

ابقَ على Spark ولا تربط Billing أو ترقي إلى Blaze إذا كنت لا تريد دفعًا. لم نتحقق من خطة مشروعك الحالية من حسابك. الحصة المجانية محدودة ويشارك فيها النظام القديم. Firebase Storage الحالي يتطلب Blaze، لذلك هذا الكود لا يستخدمه.

في Firestore → Indexes → Single field → Add exemption، أضف إعفاء للحقل `dataUrl` في collection group `photos` وعطّل فهرسته. لا تفعّل TTL. لا ننشر ملف indexes شاملًا حتى لا نغيّر فهارس النظام القديم.

حد هذه النسخة **500 سجل لكل استعلام**، و500 تسليم قديم لكل جولة تنظيف. عند تجاوز الحد تظهر رسالة توقف بدل إحصائيات ناقصة؛ يلزم تقسيم صفحات وأرشفة قبل استخدام واسع. لا يوجد نسخ احتياطي تلقائي. الصلاحيات وحدود الأحجام لا تمنع إساءة استهلاك الحصة من حساب مصرح له.

المصادر: [Firestore quotas](https://firebase.google.com/docs/firestore/quotas)، [Storage requirements](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024).

## نشر رابط عام بدون سيرفر

استخدم Firebase Hosting الثابت وليس App Hosting أو Cloud Run. الإعداد يستهدف موقعًا منفصلًا حتى لا تستبدل موقع النظام القديم:

```bash
pnpm build
npx -y firebase-tools@latest hosting:sites:create techware-portal-257053522854 --project techware-instructor
npx -y firebase-tools@latest deploy --only hosting --config firebase.portal.json --project techware-instructor
```

إنشاء الموقع مرة واحدة. إذا كان الاسم محجوزًا أو الموقع موجودًا، تحقق من ملكيته ومحتواه قبل النشر؛ يمكن اختيار اسم جديد وتعديله في firebase.portal.json → hosting.site. أضف نطاق الموقع الجديد إلى Authorized domains وجرّب الدخول. راقب حصة Hosting أيضًا. هذه الأوامر لم تُنفّذ على مشروعك من هنا.

## ملفات التعديل

| الملف | الغرض |
|---|---|
| app/platform.tsx | الشاشات والمجموعات والتاسكات |
| app/globals.css | الألوان والتنسيق والموبايل |
| app/portal-admin.tsx | الحسابات والكورسات |
| app/login/login-screen.tsx وapp/portal-gate.tsx | الدخول وتفعيل الحساب |
| lib/portal-client.ts | القراءة والحفظ والتنظيف في Firebase |
| lib/platform-actions.ts | تحقق العمليات والحسابات |
| lib/firebase-client.ts | إعدادات Firebase العامة |
| firebase/firestore.rules | صلاحيات الخادم والتحقق من البيانات |
| portal/main.tsx وvite.portal.config.ts | الموقع الثابت |

ملفات معاينة Sites/D1 القديمة موجودة للتوافق فقط؛ البناء الافتراضي لا يستخدم API الخاص بها. `pnpm dev:preview` مخصص للمعاينة القديمة، وليس بوابة Firebase.

## الاختبارات

```bash
pnpm exec tsc --noEmit
pnpm test
pnpm test:firestore
pnpm build
```

اختبار Firestore يحتاج Java 21 أو أحدث على جهاز التطوير فقط. يستخدم مشروع `demo-techware` محليًا ولا يعدّل الإنتاج. يختبر عزل الأدوار والتصعيد والرسائل والصور والحذف وكود الحفظ والاشتراكات الفعلية لكل دور. راجع `firebase/security-audit.json` لحدود قواعد النظام القديم المتبقية.
